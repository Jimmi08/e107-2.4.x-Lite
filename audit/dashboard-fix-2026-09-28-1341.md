## 2. What changed

### Commit 1: security and persistence (`eadmin/includes/dashboard.php`)

- `:25` `FLEXPANEL_ENABLED` uses the upstream gate again (`!getperms('1') && adminpref == 1` → disabled).
- The top-level AJAX save block was removed. The save now runs in `render()` (`:678`), which `admin.php` calls after `auth.php`. `auth.php` already answers non-admin AJAX requests with a 403, and `canEditLayout()` checks again.
- `:157` `canEditLayout()`: `ADMIN` and `FLEXPANEL_ENABLED`, plus `getperms('1')` when `adminpref = 1`.
- `:172` `saveOrder()`: whitelist and merge (section 4).
- `:249` `addToPosition()`: records every panel id placed on the page and replaces three copies of the placement code.
- `:747` `buildPanels()`: the panel loop moved out of `render()` so the AJAX save can build the same panel set.
- `:67` `$this->areas`: the area ids from the template `positions`.
- `:270` `getMenuPosition()`: ignores a stored position whose area is not a layout area and casts the weight to int.
- `:100` JS and CSS are loaded only when `canEditLayout()` is true.
- `:115` the `e-flexpanel-layout` handler runs only under `canEditLayout()` and accepts only keys of `getDefaultPositions()`.

### Commit 2: layout editing (`eadmin/includes/dashboard.php`)

- `:102-103` inline CSS, only when `canEditLayout()` is true: every `menu-area-xx` gets a dashed outline, a minimum height and its id as a label. The label uses `::before { content: attr(id) }`, so it adds no DOM node for `flexPanelEmptyPanels()` or sortable to see. `!important` is used because `admin.flexpanel.js` sets inline `border: none`, `min-height: 0` and `margin-bottom: 0` after each drop.
- All areas were already rendered: the layout template contains every `menu-area-02` to `menu-area-10` div, and each token is replaced, empty or not.
- `:231` `panelInfo()`: for `getperms('1')` only, it returns `<!-- dashboard-panel: <id> | perm: <perm> -->`, with both values passed through `$tp->toAttribute(..., true)`, so `>` cannot close the comment. The comment is prepended to the panel body in `core_infopanel_icons()`, `core_categories_icons()`, `addon_group_icons()` and `addon_single_panel()`, which puts it inside `div.panel`.

### Commit 3: perms (`ethemes/backend/templates/dashboard_template.php`)

- Every panel entry has an explicit `perm`: `''` = all admins.
- `:170` `core-multi-icons-category`: `'0'` → `'1'`.
- `:202` `addons-single-info-chart`: `'4'` (user management). Its user plugin tabs show online users and new users (`eplugins/user/e_dashboard.php:21`). `getperms()` supports `|` for OR (`user_handler.php:2796`), but `U0` to `U3` are narrower user sub-rights (quick add, options, ranks) and do not include the user list. The list route in `eadmin/users.php` uses `'0|4'`, and `'0'` always passes, so `'4'` is equivalent.

### Commit 4: UI bugs

- Template `:164`: `$caption = e107::getParser()->lanVars('LAN_CONTROL_PANEL', htmlspecialchars(ucwords(defset('USERNAME', '')), ...))`.
  - The constant name is passed as a string because `lanVars()` resolves it with `defset()`.

- `addon_group_icons()`: `$newarray` initialised (`:471`), plugins without an admin link skipped, returns `''` when no tile rendered (`:495`).

## 4. Whitelist and merge logic

1. The save runs only for an AJAX POST with `core-flexpanel-order` in `render()`, and only if `canEditLayout()` is true:
   - `adminpref = 1`: `ADMIN` and `getperms('1')`.
   - `adminpref = 0`: `ADMIN`.

   Otherwise the request exits without writing.
2. `buildPanels()` runs the same template loop as the page and applies the template `perm` of each entry. Each panel placed on the page is recorded by `addToPosition()`:
   - template keys whose method returned HTML;
   - `plug-infopanel-<plugin>-<n>` from `addon_single_panel()`;
   - the admin category panels (`setMenu`, `userMenu`, ...) from `core_categories_icons()` for `core-multi-icons-category`.

   `addon_group_icons()` returns nothing when all tiles are filtered, so it is then not whitelisted.
3. For each posted entry, the id must be in that set, `area` must be a string equal to one of the template `positions` keys (`menu-area-02` to `menu-area-10`), and `weight` is cast to int. Anything else is dropped.
4. The accepted entries overwrite their own keys in the stored order (core pref or user pref, depending on `adminpref`). Every other stored key stays unchanged. Nothing is saved when no entry was accepted.

Stub harness results:
- perm `1`, `adminpref = 1`: stored `setMenu` (not visible) kept, `evil` and unknown ids rejected, `'7x'` → `7`.
- no `ADMIN`: no write.
- `adminpref = 1` without perm `1`: no write.
- `adminpref = 0`: the write goes to the user pref.

## 5. CSRF

`class2.php:595` runs `e107::getSession()->challenge()->check(false)` for every request, and answers a refusal with a 403 (JSON for AJAX). The default mode is `CSRF_CHECK_TOKEN_OR_SAME_SITE` (3).

- **Cross-site POST with cookies:** refused with a 403 unless a valid `e-token` is sent or the browser vouches same-site. A browser sending `Sec-Fetch-Site: cross-site` is refused.
- **POST without cookies:** passes the check, because `hasAmbientAuthority()` is false. It is then an unauthenticated request: `ADMIN` is false, `auth.php` returns a 403 for AJAX, and `canEditLayout()` returns false. Before this change it reached the core pref write when `adminpref = 1`.
- **The dashboard's own `$.post`:** same-origin, so it passes via Fetch Metadata. `all.jquery.js` also attaches the token to same-origin POSTs.

## 8. Manual test checklist

Set perms in Admins > edit permissions. Toggle `adminpref` with "Apply dashboard preferences to all administrators" in the admin theme settings.

### Main admin (perm `0`)
- [ ] `adminpref = 1`:
  - [ ] drag works, and every area shows a dashed outline and its id, including empty areas;
  - [ ] after reload, the order is kept;
  - [ ] the page source shows `<!-- dashboard-panel: ... -->` inside each `div.panel`;
  - [ ] the category panels are shown, and the website status (chart) panel is shown.
- [ ] `adminpref = 0`: same as above; the order is saved to this admin only (another admin's layout is unchanged).

### Admin with perm `1` (not `0`)
- [ ] `adminpref = 1`:
  - [ ] drag, outlines and HTML comments are present;
  - [ ] a save changes the shared layout.
- [ ] `adminpref = 0`: drag and outlines are present; the save goes to the own user pref only.

### Admin without perm `1`
- [ ] `adminpref = 1`:
  - [ ] no drag handle cursor, no outlines, no area labels, no HTML comments, `admin.flexpanel.js` not loaded;
  - [ ] the shared layout is shown;
  - [ ] "Control Panel" caption on the icons panel;
  - [ ] no website status panel without perm `4`.
- [ ] `adminpref = 0`:
  - [ ] drag and outlines are present, no HTML comments;
  - [ ] the save goes to the own user pref;
  - [ ] the main admin's layout is unchanged.

### Special cases
- [ ] Admin with perm `1` but not `0`, `adminpref = 1`, saves the layout:
  - [ ] panels visible only to the main admin (e.g. the website status panel when this admin lacks `4`) keep their stored positions, checked in the `core-flexpanel-order` pref or by logging in as main admin.
- [ ] Unauthenticated POST, no cookies:

  ```
  curl -i -X POST https://SITE/eadmin/admin.php -H 'X-Requested-With: XMLHttpRequest' \
    --data 'core-flexpanel-order[evil][area]=menu-area-02&core-flexpanel-order[evil][weight]=0'
  ```

  → 403 JSON from `auth.php`; `core-flexpanel-order` unchanged.
- [ ] The same POST from a logged-in non-admin member (with their session cookie and a valid `e-token`, or from a same-origin page) → 403 from `auth.php`; the pref is unchanged.
- [ ] A posted unknown panel id or unknown area (e.g. `menu-area-99`) as perm-`1` admin → not stored.
- [ ] Plugin in `modules_panel` without admin URL → no PHP warning; panel hidden if no tile remains.
